# 升级与保留当前记录的回退



本版在既有状态格式上简化普通调用，恢复完整内容方法，从独立社媒自动运营skill项目构建和更新。私有账号状态沿用原位置，不随源码目录重建。

## 升级

暂停唤醒和新领取，等待当前动作结束。用原版本入口service stop正常停止自有服务，保留浏览器，不能杀发送中的进程。

私有备份包含配置、tasks.sqlite3、runtime-state.json、operation-journal.db（存在时）及未结案必要素材。SQLite用backup API，停止服务后复制索引库。记原目录、版本、程序哈希，备份不进发布包。

使用新版本独立目录，私有状态保持原位，只改必要程序路径。正常本地检查后service ensure，核对实际版本、账号、state_id、生效配置摘要、原任务与回执；队列是否恢复服从最新用户指令。暂停状态不因升级自动改变。旧手工任务不会因升级自动执行。



## 回退到0.3.6

直接恢复旧备份会丢掉升级后的发送事实，必须沿用当前记录：

1. 暂停唤醒和新领取，确认无执行中租约，用当前版本入口停止服务。
2. 配置仍指向当前版本时执行service export-legacy。
3. 该步骤持有执行锁和账号进程锁，逐条导出当前完整回执为版本1 JSON，保留期限，排期转回旧版格式。未知仍未知，不访问网站。
4. 将程序路径切回已保存0.3.6完整目录，用旧入口启动并核对原身份、任务和升级后新增结果，再恢复已有授权内的任务。

转换失败不能跳过或伪造空库。索引留原位，再升级从最新版本1补入，检查覆盖回退期间新增记录。旧版直接读版本2会拒绝，避免忽略索引继续发送。更早版本未验收，不能套用本结果。

本地索引使用固定版本bbolt，运行包带许可，独立源码包带锁定构建源码，不需数据库服务。

## 修复形成版本

保存复现依据、最小修改、针对性检查、实际本地入口验证，冻结版本，保留固定包、报告和回退路径。verify_engineering输出当前程序、全部运行模块哈希、源码提交及是否仍有未提交改动；repair核对后记录实际版本，最多20条。

scripts/verify_upgrade.py使用独立临时状态、关闭写入与不可连接的浏览器，验证进程升级、回退、再升级。选择脚本支持的旧版本目录，沿用最新任务与回执。

状态丢失时停止外发，恢复完整备份后逐项核对备份之后的平台结果。不确定就unknown。代码回退不能撤销平台已发内容或预约。
