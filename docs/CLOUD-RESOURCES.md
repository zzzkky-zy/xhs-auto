# Debian 云端轻量运行

目标是用户提供的 Debian 13.6、AMD EPYC x86_64、9个可见逻辑核心、9.7GiB内存、31.5GiB磁盘（当前剩余29.7GiB）、无显卡、远程 GPT Astra。当前没有该机器的访问连接；本机检查与Linux构建不能冒充云端实测。

## 资源怎样分配

| 部分 | 本版配置/目标 | 谁负责生效 |
| --- | --- | --- |
| 运营Go程序与每个工具转接进程 | GOMEMLIMIT=256MiB，GOMAXPROCS=2 | 私有配置默认生效；前者是软预算，不是整个进程内存硬上限 |
| 后台及其Python子进程 | 内存高水位384MiB、硬上限512MiB、最多1核CPU时间 | 生成的宿主服务配置，实际启用后生效 |
| 专用浏览器 | 内存高水位1.5GiB、硬上限2.5GiB、最多1.5核CPU时间 | 宿主已有浏览器服务的可选配置；不另开浏览器 |
| 后台和专用浏览器合计 | 内存高水位2GiB、硬上限3GiB、最多2核CPU时间 | 两者必须实际归入同一个资源组；给其他长期任务留下约6.7GiB物理内存空间 |
| 网页结果缓存 | 三类合计最多24MiB；过期后最长1分钟释放 | 程序执行，不要求模型清理 |
| 临时批次素材 | 256MiB；每次完成且通过首批验收后清理 | 程序执行；外部制图工具生成文件前也须检查剩余预算 |
| 任务、回执、程序日志等状态文件 | 512MiB新工作准入预算 | 超限保留证据并等待清理/扩容，不删防重发信息 |
| 运行日志 | mcp.log约16MiB总量；启动日志约3MiB | 自动轮换，限制单次日志读取大小；不输出认证内容 |
| 整机磁盘余量 | 两个工作分区均保留至少2GiB、1024个可用文件编号 | 新批、入队、复制素材和任务领取前检查；资源恢复后原任务可继续 |

这些是配置预算，不是已测得的实际占用。CPU配额的100%代表一颗逻辑核心的CPU时间；两核的合计配额是整机9个可见核心的一部分。内存高水位会施加回收压力，硬上限可能终止超限进程，因此同时保留任务租约、未知发送保护和有限重启；不能用自动重启绕过未知发送。

硬限制不包括宿主agent、其他任务或未归入该组的工具转接进程。Astra与图片生成使用宿主提供的远程能力，本包不下载模型权重、不安装本地图片模型，不要求显卡。图片仍逐张制作和检查；不同时启动多批制图、多个浏览器或多份同账号后台。

## 初次配置与宿主限制

1. 使用`linux-amd64`完整包；运行只需Python标准库、匹配浏览器及现有接入能力，无需Go、Docker、桌面系统或本地模型。私有配置、状态、素材和浏览器profile放持久磁盘，分开于程序版本。先按[本机入口](CODEX-LOCAL.md)配置并绑定一次；迁移同一账号必须正常停止旧主机执行，使用完整状态与最终发送事实，不能两台主机同时运营。
2. 新配置的示例已包含轻量默认值。已有云端配置执行`python3 scripts/cloud_host.py --config <私有配置> apply-profile`，只更新资源/保留期限，不改账号、路径、写授权、内容质量或日程。然后执行`inspect`取得无平台访问的报告；同版本资源参数通过空闲的`service ensure`生效。
3. 如果宿主有可用的systemd用户服务，执行`python3 scripts/cloud_host.py --config <私有配置> write-units --output <新的私有目录> --browser-unit <宿主已有专用浏览器.service>`。省略最后一项只生成后台配置；不得声称浏览器已受限。命令只生成可审查的配置文件，不注册、启动或替换服务。确认浏览器服务归属后由宿主安装到用户服务目录、重新加载并在安全空闲点启用。先用原入口停止旧后台，再使用生成的前台服务；不能同时保留两套常驻入口。
4. 云端容器没有systemd用户服务时，直接使用平台的进程资源组/容器限制提供相同预算。本包不尝试取得管理员权限或安装第二套服务管理器。缺少宿主硬限制时，报告`hard_limits=unverified`，不能称已完成整机内存隔离。
5. 浏览器继续使用同一专用profile。宿主正常启动时可设置`--disk-cache-size=134217728`、`--media-cache-size=33554432`，只约束两类缓存；不能当作整个profile限额。不要为了改参数反复重启、复制profile或删站点存储。宿主有存储配额时给专用profile设置约1GiB预算并监测实际增长；无配额时至少每小时记录profile大小与可用磁盘，超出预算在安全点释放自有页面并由宿主处理缓存，不能盲删Cookies、IndexedDB、Local Storage或登录库。

资源组生效后，宿主核对后台和浏览器实际组归属、`MemoryCurrent/MemoryPeak/MemoryMax/CPUUsageNSec`和`memory.events`。`inspect`能读取自身所处Linux资源组，但它从agent启动时不一定与后台同组，不能用该值冒充整个运营组占用。不修改整机交换内存、其他任务优先级或宿主浏览器权限。

## 文件与空闲成本

每批新搜热门池，只保留当前批所需内容。素材、截图和改稿都在带所有权标记的`operation-runs/<run_id>/work|final|sealed`内；不能把每轮完整聊天、网页HTML、图片与多份最终稿复制到根目录、桌面、Downloads或日志目录。首批待验收、运行中、blocked和unknown证据始终保留。已完成批次立刻清理；明确放弃的批次默认72小时后清理。

独立查询任务的完整结果默认保留24小时，之后删除；若仍是其他任务的前置条件，只保留小型结果标记。独立写任务的完整参数/响应默认保留7天，之后保留任务编号、原指纹、状态及小型目标记录。批次任务仍按实际验收规则清理，不提前删除首批材料。永久回执与防重发记录不按天删除，体积会缓慢增长；512MiB预算与磁盘余量防止其挤满机器，长期无限外发且永久保存全部发送事实不可能实现严格零增长。

后台每小时及finish/accept维护一次，队列暂停时仍清理已完成资料，不触发平台请求。SQLite空闲页会复用，不在运行时全库压缩。空队列的Python启动频率由每分钟1–4次降为每小时1次；等待已安排任务时直接等到其真实期限，新入队/启用/恢复通过事件立即唤醒。旧版未知状态仍有限查本地回执，不以搜帖探测登录或解封。

自有研究页空闲5–15分钟后由轻量程序定时关闭，正在用的页面、未知发送页面及用户页面保留。过期缓存一分钟内清除；空闲维护不打开新网页。agent保存任务号和下一时刻后结束本次执行，由宿主唤醒，不能长睡、每几秒查进度或每次加载全部视觉资料。使用相关模块时只读该模块，图片逐张生成后保存，尽快释放工具返回的大图/原始网页文本。

自动修复只保留当前程序、一份已验证回退程序及一份必要状态备份；成功升级并核对后，删除自己创建且不再引用的旧安装包、候选、测试输出与构建缓存。需要编译时才取得锁定工具链，最多两路编译；构建缓存必须使用本项目自有目录，结束后清理，不能清其他任务共用缓存。磁盘检查不递归扫描这些来源不明目录，余量保护仍覆盖所在分区；宿主需定期核对整个专用运营目录，不把外部备份写成无上限历史。

## 云端验收与后续运行

云端agent先用本地诊断确认版本、实际所需工具能力、队列持久化、日志轮换、资源组限制及重启；不把历史发布重新发送。随后按实际授权和首批验收状态继续。首个24小时、72小时记录后台与浏览器峰值内存、CPU累计、可用磁盘、profile体积、状态库/素材体积、文件数、异常退出和未知发送数，比较是否进入稳定区间。无异常时保留一份滚动摘要，不按每次检查创建新报告文件。

配额超限或磁盘不足时停止增加工作、保留原任务；空间恢复后5分钟内的本地检查可继续领取，不要求重新授权、不重抽发布时间、不因资源优化放宽评论间隔。只有证据无法判断、登录验证或宿主权限确实需要用户处理时再介入。长期真实资源曲线只有在该云端实机运行后才能确认。

机制依据：[Go内存软限制](https://go.dev/doc/gc-guide)、[systemd资源控制定义](https://github.com/systemd/systemd/blob/main/man/systemd.resource-control.xml)、[Chromium缓存类型](https://www.chromium.org/developers/design-documents/network-stack/disk-cache/)。预算数值是本项目为该机器制定的起点，后续依据真实峰值调整。
