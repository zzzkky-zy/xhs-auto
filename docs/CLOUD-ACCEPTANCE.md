# 云端实机验收

目标宿主的系统、架构、CPU、内存、磁盘和浏览器由执行agent实际检查；选择对应运行包。资源入口见[CLOUD-RESOURCES](CLOUD-RESOURCES.md)。本机检查与交叉编译不代替目标宿主实跑。

执行agent只需保存一份滚动检查结果，后续更新同一文件，不每次生成新报告：

1. linux-amd64运行包哈希匹配、Python标准库可用；不安装Go/Docker/本地模型作为日常运行要求。
2. 明确持久磁盘、账号绑定、当前任务与回执，原主机已停止接纳该账号新任务；重启后原状态仍可读取，缺失不建空库。
3. 宿主已有浏览器CDP可达，固定专用profile可由用户接管；不自行启动第二浏览器或复制登录资料。实际身份验证及首批验收仍按原业务授权。
4. 必需工具能力与版本正常，普通读取不依赖任务库；一次内容调用内部归账，长任务排队、查询与重启无重复；不重跑历史发布。队列空闲、暂停及资源不足时不访问平台。
5. 应用轻量配置，并核对实际后台和专用浏览器资源组/硬限制、CPU配额、内存峰值、磁盘及文件数。生成服务文件、读到宿主总内存或看到GOMEMLIMIT都不能代替硬限制已生效。
6. 宿主提供唤醒及已有授权通知渠道；入队后agent可以结束本轮工作，按下一时刻接续。默认不自行创建日程，每日数量和执行时段由用户与执行agent灵活约定。
7. 先记录24小时、72小时实际资源曲线，确认非必要素材、过期响应与缓存回落；按实际授权逐步验证登录保持、页面异常及结果未知的接续。没有实测不能宣称7×24稳定、永久登录或不会触发平台限制。

自动修复保留实际源码/skill改动与验证，只留当前及一份回退版本。验证码、掉登录、账号不一致和发送无法确认保留现场，按实际需要人工介入；资源不足不以清除发送凭证或重建profile解决。

24/72小时观察沿用一份表，记录每个时间段的授权动作数、首次成功数、额外尝试数、unknown数、实际网页请求量、执行耗时、掉登录、验证码、300013及人工介入次数，并记录后台/浏览器CPU、RSS、状态与素材磁盘量。缓存命中不记网页请求；制作与等待和实际网页动作耗时分开。没有必要的自然授权任务时记录空闲，不能额外外发做压测。当前未连接目标主机，表格与构建物只用于接续，不能填写虚构观察值。
