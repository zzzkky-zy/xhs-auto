# 发布确认与定时确认保护 · 0.2.1

发布结果以平台明确回执和原任务记录为准，不能以正文含有“发布成功”、隐藏旧提示或跳离页面判定成功。

0.2.1改为：

- 提交前要求素材确实就绪、已审标题匹配，用户要求的长文标签不可静默丢弃。
- 主发布按钮只点一次；只有明确的可见定时发布弹窗内才点击确认，不再次点击页面主按钮。
- 提交前保存旧提示节点；成功提示须是新出现且可见的提示，排除正文、编辑区域、旧可见或隐藏节点。
- 明确成功页须是HTTPS创作平台的 `/publish/success`；跳到首页、登录、验证或无关地址不能单凭URL计成功。
- 资源、按钮和回执等待都服从调用方取消与有限期限。开始提交后的未知结果仍由账本拦住重复发送，先查询记录和创作中心（包括定时待发）。

实际创作平台可能有其他回执布局；未匹配时报告未知，须在获准的单篇发布验收中核对后补适配，不能把跳页或没有报错当成功。

`publish_fixture_test.go`覆盖上述负例、新旧提示、明确弹窗单次确认、标题缺失/不符、真实提交辅助函数单次点击，以及取消按钮等待；`publish_receipt_test.go`覆盖成功、首页、登录、验证与无关地址。具体测试数量及时长见 TEST-REPORT。

升级使用当前固定包，沿用原私有状态，不能清空账本。
