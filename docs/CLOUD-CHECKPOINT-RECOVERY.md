# 本地私有备份与隔离恢复

## 对使用者意味着什么

本功能把三本运营账本、每次任务的完整工作目录、账本中明确记录的文件引用和额外指定证据一起保存。缺少已知文件就拒绝，不能把丢失的库当成空白新账号。恢复只开一个新的隔离目录，不替换正在使用的账本，也不恢复发帖或评论。

“检查完整”不等于“已经最新”。一份旧备份即使一页不缺，也可能没有包含后来发生的评论或发布。工具始终返回 `latest_verified=false`；即便提供外部保存的摘要，也只证明与那个已知备份一致，不证明比平台上的事实更新。

## 接口与边界

```sh
python scripts/cloud_checkpoint.py create --config /private/settings.json --destination /private/new-checkpoint --required-file /private/extra-evidence.json
python scripts/cloud_checkpoint.py verify --checkpoint /private/new-checkpoint
python scripts/cloud_checkpoint.py restore --checkpoint /private/new-checkpoint --destination /private/new-quarantine
```

`verify` 和 `restore` 可额外传 `--expected-checkpoint-digest`，必须来自独立可信保存的值。摘要不符拒绝；不会靠事件数量、最大编号或时间推断谁更新，不自动合并分叉。目录必须全新且父目录已存在，不覆盖现存目录。

只支持已停止写入的可信本地 cloud_host 状态。三库须有真实既有历史、精确账号与状态身份匹配、所有 run owner 匹配；非空 WAL/journal/shm 拒绝。使用 SQLite backup API 分别备份，前后重复检查全部源文件及目录清单。任何检测到的变化拒绝，留下带 INCOMPLETE 标记的不可用产物。不是跨库原子事务，不抵抗恶意源文件先改变再还原的 ABA 攻击；不能拿这个检查代替实际停写。

覆盖范围是三库、所有数据库登记的 run 目录、数据库 JSON 中明确文件字段的绝对路径引用、明确提供的额外文件。缺失已知引用、未知外部目录、链接或不支持的结构拒绝。明确 file/path/asset 字段若带历史 sha256，会逐项比对；不符、错误摘要类型或路径穿越均拒绝，绝不改历史摘要。缺摘要的旧引用在 unverified_historical_paths 单列，不能宣称已核实历史一致。普通正文和 URL 不当作文件路径。散落在自然语言中的文件路径、未写入账本的素材，以及未告诉工具的外部文件无法自动证明存在，因此不声称“恢复了原任务的一切材料”。调用方必须列出额外来源、阶段记录和证据；若不清楚是否还有材料，不得据此通过完整运营交接验收。

## 敏感信息：绝不能当公开源码包

备份不复制原配置内容、浏览器登录目录、环境变量或额外凭据文件。原配置只留摘要和来源路径。材料中若出现原配置或常见凭据文件名（如 .env、私钥），整个备份拒绝，不偷偷跳过后声称完整。文件名检查不能识别任意正文中的秘密，工作目录自身也必须按敏感资料对待。三库保真，因此库中的历史 xsec、领取凭证相关值或其他敏感事实可能仍存在；`may_contain_credentials=true`。保真与自动全面脱敏不能同时承诺。本工具只在本地创建私有目录（0700）和文件（0600），没有网络、上传或公开分享功能。不要把其产物放入公开项目、发布包或云端共享资料。

清单也可能含账号标识与私有路径，不是公开报告。CLI 输出仅摘要/状态/稳定错误码，不回显配置、SQL内容或文件正文。若需要公开报告，应另用白名单字段生成摘要，不得把脱敏报告当可运行的原库。

## 隔离恢复契约

恢复先写 `<destination>/RECOVERY-QUARANTINE.json`，以及 `<destination>/evidence/state/RECOVERY-QUARANTINE.json`，之后才复制清单中的文件。标记 schema 为 `xhs-recovery-quarantine-v1`，`execution_allowed=false`，`latest_verified=false`。当前运行时必须拒绝配置指向此目录或其子目录时的写入；普通解除暂停不能移除恢复隔离。

数据库保存在 evidence/state；素材保存为 evidence/materials 中编号文件；另有来源路径映射供人工审查。不会重写不可变历史绑定、旧文件路径或回执，不生成可启动账号配置。未知结果仍未知，既有暂停记录保留。标记本身不替代运行时门禁，也不使不识别标记的旧版本安全；严禁拿旧版本启动隔离库。

成功恢复才写最终 checkpoint.json。中途失败可能留下半成品，但隔离标记已经存在，不能当作成功恢复。恢复后的下一步是独立核对备份之后的平台事实、当前精确身份与权限，解决未知记录，再设计受控迁移；此脚本没有解除隔离、自动迁移、重领旧操作或启用命令。

## 已验证范围

测试只使用临时目录与真实运行时创建的合成数据库，覆盖缺库、缺 run owner、缺结构化材料、侧车文件、源变化、链接、篡改、已有目标、恢复中断、未知与暂停保留等。不访问真实账号、不测试小红书发布、不证明遗失的旧账号材料已经恢复。

历史摘要冲突时，本地调用异常的 `conflicts` 属性包含具体路径、预期摘要与实际摘要，仅供私下诊断保存；命令行仍只输出错误码，避免在日志里泄露私有路径。
