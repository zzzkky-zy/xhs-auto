# 评论卡住与超时：诊断与恢复



回归先复现旧判断把任务变为blocked，修复后同一任务经过失败、恢复、等待、到期、成功全程只有一个编号；未知保护与错误回执校验通过。真实第二条恢复仍以原编号平台确认回执为准。



修复只在原交互前激活本次任务页，回复在滚动目标前也激活；不跳过遮挡、草稿和身份检查，不改为坐标强点或DOM赋值，不增加发送点击。其他页面保留。该证据定位并修复了后台页交互故障；两条真实失败是否已恢复仍以原编号的平台确认回执为准。


## 修复

- 评论/回复使用调用方的取消和截止时间；原先主动忽略外层 ctx、回复页面允许跑5分钟。现在单个评论动作最长120秒，准确目标查找最多45秒，关键页面初始等待最多8秒；较短的调用期限优先。已移除展开、输入和发送点击另外叠加的8秒子期限，沿用整条动作的取消与截止时间。
- 等关键容器，不等待整页 load；图片或第三方资源未加载完时，已出现的评论区可继续处理。取消后不再继续输入或开始提交。
- 查找一次读取已渲染评论；提供 comment_id 时只认这一条，不回退到同作者的另一条；只有 user_id 且已加载区域有多个候选时报目标不明确。实际任务应保存完整读取所得的准确 comment_id。
- 查找、展开、滚动有限；同一展开按钮只点一次，连续无新增评论时停。没有找到就保留准确目标和阶段，不反复搜帖。
- 浏览器握手与长期事件连接分别管理；任务新建页面时鼠标/输入设备也绑定任务上下文。页面与输入设备共用有效任务上下文；实际鼠标检查不能被工具清单检查代替。
- 在任务页面核对实际发送账号；输入前、发送前分别只读当前页，不额外导航。已有草稿不覆盖，输入内容不完整不点发送。
- 只点一次发送；开始调用发送点击后发生任何不确定异常都视为可能已提交。
- 确认最多12秒；要求当前账号、准确正文、目标评论区/线程内的新评论 ID、输入框清空、节点持续至少1秒，并检查可识别失败/受限提示。编辑框文本、旧评论、其他作者同文和短暂出现后被拒绝的节点不算成功。它仍是网页可见证据，真实平台回执、评论 ID 规则及楼中楼结构须在账号验收确认。





## 如何恢复

未调用发送点击的已知失败为 `ERR_COMMENT_NOT_SUBMITTED`，服务保存 `not_applied` 和阶段。只有导航/关键页面等待超时且明确没提交的临时故障有限延后，保留原任务、参数和批准依据，总尝试默认最多3次；沿用实际已保存的共享写期限与必要短暂退避，不再额外固定等3分钟。用完次数或目标不符转待处理，验证、登录和权限错误立即暂停账号。当前节奏以[RUNTIME.md](RUNTIME.md)为准。

开始点击后的失败为 `ERR_OPERATION_UNKNOWN`（内含 `ERR_COMMENT_CONFIRMATION_UNKNOWN`）；队列未知，暂停后续写入。先查 `get_operation_status` 与实际平台结果，再决定恢复。客户端断开但未拿到上述未提交证据时也按未知处理，不凭“超时”重发。

参考配置的客户端期限180秒；不再依赖默认60秒的未锁版 mcp-remote。dot 宿主自己的工具期限仍待确认，不能假设可任意拉长。若宿主期限短，采用其支持的队列唤醒/查询入口；该模式须单独适配。服务请求最多3分钟，任务页面清理另有最多5秒期限；等待锁、登录和网络也消耗预算，预算不足会明确结束，不保证每条回复都在60秒内完成。

## 本机浏览器用例

`scripts/test.py --fixture-chrome <Chrome路径>` 包括实际点击、按段原生输入和确认流程，覆盖：主帖评论、准确线程回复、超过旧4秒的延迟显示、只留输入框而没有回执、其他作者同文、历史同文、暂时显示随后被拒绝、账号改变、输入框缺失、按钮禁用、验证码、准确回复目标不存在、取消查找及浏览器事件连接接续。测试缩短阅读/输入间隔，只访问本机模拟页面；测试时长见 TEST-REPORT，不将其当成真实账号的速度或风控表现。

Go 账本另测提交前/提交后的不同落盘状态及重启；Python 执行器测未提交待处理、可确认页面超时有限延后、验证暂停账号、未知不能盲重试。真实账号的页面结构、评论权限、验证频次和外部回执仍未验收。
