# 临时集成测试的失败证据

2026-10-22的一次全量执行共757项，3项失败、1项跳过。保留该失败事实，
不能用后来单次成功覆盖，也不能没有证据就归咎平台或运行环境。

已确认其中readiness失败时HTTP服务实际上启动且/runtime返回200，但耗时768ms，
原测试每次只等200ms，造成错误的“未启动”判定。现每次探测最多1秒且不超过
剩余总预算，总deadline仍5秒；进程已退出则提前停止。成功仍核对真实响应中的
账号、state_id和配置指纹，没有放宽就绪断言。

另两项ERR_TASK_EXECUTOR发生时，旧Go二进制没有保留执行器退出原因，旧测试
又在失败后清理了日志，因此原始底层原因不能追回。随后仅临时fixture的诊断运行
3项通过，不证明原问题已修复。Go源码错误分类是否已编译进测试二进制，必须单独
说明，Python回归成功不能替代未运行的Go测试或未完成的构建。

## 保留以后失败时的证据

    mkdir -m 700 /private/test-diagnostics
    XHS_TEST_DIAGNOSTIC_DIR=/private/test-diagnostics python -m unittest discover -s tests -q

仅失败时创建0600 JSON报告，成功不生成报告；未配置目录则不持久导出。
报告记录探测/请求阶段耗时、错误类型/代码，以及backend/proxy日志的hash、大小、
状态和时延摘要。**不导出原始日志、正文、token、私有命令或配置**。
因此这是脱敏诊断摘要，不是原始日志备份，也不保证单凭它可以找回所有底层原因。
输出目录应保持私有；导出失败只输出固定提示，不掩盖原测试失败。

确定性测试覆盖768ms响应、总deadline、提前退出、无效身份拒绝、secret脱敏、
文件权限、成功不留文件，以及真实临时fixture在失败清理前自动导出。

## 明确业务拒绝与执行器故障

查询一个不存在的任务现在统一返回`ERR_TASK_NOT_FOUND`：对普通用户的意思是
“当前保存的记录里没有这个任务，不能据此补记成功或重新发送”。它不是“程序启动失败”。
此改动只把原有“task not found”拒绝变成稳定机器码，任务和事件账本保持不变。
缺记录仍需按交接完整性流程核对，不自动创建任务、不重发，也不放宽unknown保护。
