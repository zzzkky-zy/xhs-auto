# 当前运行规则

本文件是工程执行规则的唯一入口。普通MCP按需执行，沿用原生点击、按段输入与单次提交。每项动作使用新页面；成功关闭自有页面，明确未提交的失败保存诊断后也释放自有页面，可能已提交及unknown保留现场。用户页面与浏览器会话不动。页面复用、冻结/恢复、输入租约和阶段估时取消保持移除。工程与完整内容资源统一版本；云端资源见[CLOUD-RESOURCES](CLOUD-RESOURCES.md)。

## 三处各管一件事

| 部分 | 唯一职责 |
| --- | --- |
| agent与skill | 按当前约定研究、准备素材和自审，决定下一步；首次完整批次仍需用户实际验收 |
| tasks.sqlite3 | 原任务编号、依赖、实际状态、尝试次数与租约；批次只记准备进度和汇总 |
| 浏览器执行程序 | 串行网页动作、真实账号核对、下一次期限；operation-journal.db保存历史回执索引 |

同账号只由一台主机管理，同配置共用一个后台。宿主提供已登录浏览器、持久磁盘与备份、退出后的唤醒和必要通知。本包不另开浏览器、复制profile、自己登录或创建云端日程。

## 节奏与减少请求

帖子采用平台预约时间，相邻对外发布时间随机60–90分钟。schedule抽一次存入唯一排期表ops_calendar，重启和移交沿用。每条发布任务独占一个位置，已提交的位置不变。replace_unsubmitted重排剩余位置；已入队任务先逐条取消，再安排替代任务。取消只能作用于尚未领取的任务。

最终审查前核对当前发布页支持的时间档位与已保存排期；当前已验证页面按半小时档位发布，不能把请求中的任意分钟、秒直接当成后台实际时间。按该档位预核相邻实际发布时间仍在60–90分钟内；确需调整时只走现有schedule/replace_unsubmitted流程处理未提交位置，不手改排期库、不为挑时间反复重抽。分别保存请求时间与后台确认时间，提交成功后只读核对后台的标题、封面、定时状态及时间；显示差异记录到交付材料，不为核验重复提交，已提交位置不自动改动。

评论、回复及其他写动作共用随机60–180秒期限，由浏览器执行程序在实际动作前抽取并同步保存。队列读取这一期限，不再另抽或另加固定等待。预约提交也串行受共享期限限制，默认另有60秒提交下限；对外发布时间与现在提交预约的时刻分开记录，不再默认额外等90分钟提交下一预约。旧版未到期的期限继续保留。

搜索与读取分别使用search_interval_min_seconds/max_seconds和read_interval_min_seconds/max_seconds；写动作使用write_interval_min_seconds/max_seconds。旧*_interval_seconds仍明确配置时兼容原固定值，新增范围覆盖对应端点。改配置只影响以后新抽取的期限，不重抽现有期限。

所有实际网页动作（读取、身份检查和写入）另共用一个10–20秒随机操作期限，保存在原runtime-state.json的next_action_at，不新建任务库。新读取同时保存读取额度；写入只更新共享操作期限及原写入期限，不扣读取额度。查询通知、私信列表、只打开会话以及身份检查也受读取额度限制。相邻不同类型动作取各自限制中更晚的时刻，不能靠交替读写跳过等待。首次身份检查占用一次网页读取，后续业务若尚未到期则返回期限，下次复用身份缓存沿原动作继续；业务fresh只刷新内容，显式check_login_status(fresh=true)才强制刷新身份；没有提交前的等待不写成未知发送。

| 动作 | 默认预算或缓存 |
| --- | --- |
| 新搜索 | 随机60–90秒，滚动一小时20次 |
| 新搜索、推荐、详情、主页、通知及私信读取合计 | 随机10–20秒，滚动一小时120次 |
| 搜索/详情结果 | 默认15分钟，注明cached及原read_at |
| 普通读取缓存 | 默认30秒 |
| 每类网页缓存 | 最多32项、8MiB；单项2MiB，三类合计24MiB |

热门池每批实际重搜，同批短期复用；fresh不绕过预算。缓存命中和本地查询不导航、不扣网页额度。登录检查读取实际身份，不以搜帖页作探针，默认关闭周期导航。以上是运营参数，不是平台公布的安全阈值；随机节奏不能保证不出现300013。

未到期限立即返回下一次时刻。普通调用保存原编号及期限后返回，宿主到点沿原编号接续；显式启用的长任务队列到点继续，不用agent长睡或反复调用网页。某篇等待不拖住到时评论或其他独立任务。本地排队不消耗失败次数。

接续动作依据最近返回的期限判断：发布同时受共享动作期限、共享写入期限和发布提交期限约束，取适用期限中的最晚时刻；其他动作同样合并各自适用限制。本地ERR_RATE_LIMIT返回了更晚retry_at时沿用该期限，不立即再试，不为等候反复查询状态。等待期间优先整理来源、编辑稿件、检查已生成图片或更新交付材料；网页动作仍按同账号串行和实际期限执行。

后台每轮只启动一个Python执行进程，不再先查状态再执行。background_next_at合并自动任务期限、运行租约、有限恢复与每小时维护期限；空队列或暂停时按维护期限休眠，新任务/启用/恢复立即唤醒。暂停时只维护本地已完成资料，不触发恢复探测或网页动作。CLI手工入队仍默认不参与自动执行。

## 配置一次与接续

首次配置见[逐步引导](../skills/xiaohongshu-operations/references/first-time-setup.md)。默认当前设备，runtime/onboarding.py自动准备包外目录；先登录、逐项了解业务、说明禁区及默认策略/动作、明确运营任务，再用1篇帖子与5条评论的本地样稿收集口吻反馈。真人封面可选，拒绝无需照片。样稿不入队、不发送、不代替首批验收；不询问长期运行与通知设置。

私有配置放包外，路径相对配置文件或用执行主机绝对路径。account_id是本地别名，expected_user_id是平台实际用户ID，expected_state_id绑定原队列与回执。技术开关不代替用户授权。

首次init-state绑定；已有绑定但文件丢失时禁止创建空库。默认allow_write=false。正式入队复制已审查的固定素材字节，领取前再次核对。每日数量、题材和时段放本批计划，不写死旧50/200/5/30。

搜索、读帖和本地诊断直接使用对应MCP，不初始化批次或任务库。普通内容发送仍需实际授权和已审稿件，直接调用四类原工具即可在内部核对、封存素材、保存原编号任务、执行和归账；不启用队列。详情见下文。

跨时间或需要重启后自动继续的长任务才显式submit_task；沿用现有任务库、排期与回执库。manage_operation_run仍提供configure、begin、准备进度update、schedule、review、finish及首次accept；基础字段见原持续运营参考。control_task_queue暂停只影响新领取。

每条任务实际状态是执行依据：queued → running → succeeded/confirmed、failed、cancelled、blocked或unknown。finish允许明确失败、取消与成功条目一起结案，outcomes逐项计数；部分成功不说成全成功。正在运行、待处理或未知时不能清理结案。首次accept仍需实际用户验收及每类启用流程的成功实测。用户已明确授权本次发布并免审时，validation_required批次使用已有指令作为approval_ref正常执行；accept是长期模式验收，不是本次逐条审批前置。

## 配置怎样真正生效

runtime/codex_mcp.py不再为普通连接打开Store或初始化内容审查；转接仍核对实际/runtime的账号、state_id、版本、存储错误和config_fingerprint（生效配置摘要）。本地get_runtime_status在任务模块不可用时仍返回Go执行状态，并明确报告任务诊断不可用，不把高级模块错误伪装成浏览器掉线。配置只在一处转成Go参数，默认值参与摘要。

同版本普通参数变化时，service ensure只在自有服务空闲、没有运行租约时更新。先停止接纳新动作，再正常停止、重启并核对摘要；浏览器、队列、期限和回执保留。执行中返回ERR_CONFIG_PENDING_RELOAD，下次空闲ensure再应用，不打断发送。持续连接的代理可发现同一配置的普通改动，无需重连。

账号、状态、版本或认证不符时报错并保留现有服务。跨版本先用原入口停止原服务，再切程序目录。更换监听端口/URL须停止旧服务并重新连接入口，不能只改文件留下旧进程。

## 持久记录与资源

tasks.sqlite3保存任务及短期参数；runtime-state.json版本2保存身份、期限和少量未解决动作；operation-journal.db用本地索引保存历史回执、指纹及计数。历史查询按编号或指纹读取，不扫描或常驻全部历史。索引缺失或身份不符会停止，不偷偷建空库。

旧版本1完整JSON只在首次升级时导入索引，保留成功、未知、去重及期限；in_flight重启转unknown。索引事务先写回执，再更新小状态文件，中断后以已写入回执为准。目录0700、文件0600，凭据不进程序包。

完成且已通过首批验收的批次立即删带所有权标记的自有素材目录，压缩大参数和响应；明确放弃的批次默认留72小时。每小时及finish/accept清理，MCP释放自有空闲页和缓存。未知、待处理、活跃、待验收资料保留；不清用户其他文件、浏览器profile或来源不明目录。

批次素材默认256MiB；独立任务的读取完整结果默认留24小时，独立写任务的完整参数/响应留7天，分别由retention.read_keep_hours/write_detail_keep_days配置。过期读取无依赖时删除，有依赖时留小型结果标记；写任务一直保留原编号、指纹、状态及小型目标记录。待验收、活跃、blocked、unknown批次不提前压缩，升级为旧已结束任务保守地从升级时开始计时。SQLite限制2MiB页缓存，清理后复用空闲页、不在线全库压缩。

resources默认Go软预算256MiB、最多2路并行，传给后台及转接进程并参与配置摘要。state_disk_limit_mb默认512管理state_dir根层文件，包含任务库、回执索引、状态和日志；min_free_disk_mb默认2048、min_free_inodes默认1024同时检查状态及素材分区。新批、入队、复制和领取前检查，不足时ERR_RESOURCE_BUDGET或不领取；已入队任务不扣尝试次数，background_next_at最多5分钟后重查资源，恢复后继续原任务，不额外授权或重抽节奏。回执、未知证据、profile和来源不明文件不靠删除来腾空间。备份、版本包、外部制图及浏览器不在此目录预算内，磁盘余量保护覆盖所在分区，具体宿主限制与外部工具边界见云端说明。

队列暂停仍每小时维护。Go内部每分钟只清过期缓存，不另做页面冻结或闲置页面生命周期管理。正在运行、可能提交/未知保留页与用户页不动；明确未提交的失败先保存诊断再释放自有页面，避免它们累积堵塞后续写入。保留的待核对写页面达到两页时停止新增写页，等核对现场。mcp.log轮换约16MiB，supervisor.log约3MiB，日志单次读取不超过64KiB。已完成准备记录最多近期50批，诊断事件最多10000条，修复记录最多20条。小型永久回执仍会缓慢增长，不能声称无限运营且严格零增长；资源组硬限制、浏览器profile和长期曲线须在云端实测。

## 异常和实际修复

本地ERR_RATE_LIMIT明确未执行：保留原任务和retry_at，到点自动继续。真正ERR_RATE_LIMITED/300013保留进度，不用重复探针续撞；搜索限制只拦搜索，身份或写动作遇限则拦对应操作。静默截止不代表平台已解封。

浏览器短暂失联或明确未发送的临时页面故障有限重试；验证码、掉登录和账号不符保留现场。正常验证后仅凭晚于阻塞时间、匹配账号的新鲜身份记录有限恢复原任务。权限、授权、额度和未知身份不能自动绕过。

评论目标失效或同一步定位失败且没有新的恢复依据时，不由agent反复手动恢复同一任务。先按原编号读取明确not_applied回执；已确认未发送且目标选择在本批授权范围内，才通过现有管理入口取消原条目、保存替换关系，并以已读的合适目标替换。替代项沿用剩余数量和评论策略，重新完成其内容阶段与审查；未知、仍运行或只有客户端超时的条目不得替换。不同目标重复出现同类故障时停止该类外发并诊断，不连续换目标试探；程序允许的有限自动恢复仍按原契约处理。

发送结果不确定：unknown停止自动队列的后续写入，按原编号查回执和实际平台结果。独立直接调用仅在用户明确新增授权后执行不同目标，保持旧队列暂停、旧unknown原样保留，并逐项保存新编号、内容及平台回执；不能把旧未知任务换编号再发。succeeded/confirmed才结束，not_applied才可重排；找不到不等于未发送。人工核对工具默认关闭，临时启用须实际证据，不能凭超时或主页暂未显示就改结论。

普通修复保存依据，在独立版本做最小修改，完成相关检查与实际本地入口验证，冻结源码后生成verify_engineering报告，再验证升级回退。repair须提供verification_report；版本、冻结状态、必需工具能力、实际工具清单、全部退出码、当前程序及全部运行模块哈希不符时拒绝成功记录。该入口记录已完成修复，不凭一句话改源码或发布版本。内容标准与工程改动在同一版本中核验，修复不得丢失已合入的预设、文字约束与质量标准。

备份回退见[升级恢复](UPGRADE-ROLLBACK.md)，证据见[检查记录](TEST-REPORT.md)。本版不宣称云端部署、首批内容质量或7×24已经完成。

## 普通发送一次调用

post_comment_to_feed、reply_comment_in_feed、publish_content、publish_with_video保留原工具名和内容参数，可选run_id、approval_ref与operation_id。管理字段不参与原内容指纹；原操作编号、防重发与未知保护不变。

已有当前配置时，发送前内部按账号、工具、完整目标、文字、素材及排期唯一匹配有效审稿。run_id可明确指定原批；无run_id时只能唯一匹配，缺失或多义即报错，不能猜。首次验收批使用已有真实授权引用；已验收持续授权沿用原授权。素材封存后字节再次匹配，必需话题、预约时间和素材不降级。

一次调用内部完成原审核、auto_run=false任务保存、Go执行与持久回执归账。返回稳定operation_id；本地等待、取消、断线后继续沿此编号查询/接续，不换号重发。明确未提交保留可接续诊断；已提交或未知不会因调用失败重新发送。旧队列执行中的任务复用原编号，由原队列完成归账，不嵌套创建任务。

终态重放只读原回执，仍核对原请求：改正文、目标、话题、预约或现存素材字节即返回ERR_RECEIPT_MISMATCH。小型request_binding随原任务保存，不改变原指纹；素材清理后，原请求仍可读取原成功结果。旧记录缺绑定且素材已清理、无法准确核对时返回ERR_RECEIPT_QUERY_REQUIRED，改用get_operation_status查询原编号；任何终态回执缺失都不能重新发送。

旧submit_task(auto_run=false)→直接MCP→reconcile_task流程继续兼容，reconcile仅用于修复历史漏记账，不再是日常额外步骤。四类内容写工具统一核对Go持久回执，缺失、不匹配或未知不能记成功。直接调用不启用旧队列、不改变其他任务，也不扩大授权数量。独立Go程序未配置运营桥接时保留原接口兼容；已配置环境不能通过省略run_id绕过审稿。
