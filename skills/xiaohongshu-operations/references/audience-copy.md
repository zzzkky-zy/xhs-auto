# 对外文案：禁止声明、解释与免责附注

这是所有小红书内容的硬性要求，起草、配图、编辑和最终审查都执行。标题、正文、封面、全部内页、漫画对白/旁白、图注、截图/样机内文字、贴纸、小字、页脚、水印文字、互动话术、CTA、评论和回复均不得出现声明、解释类附加文案。不能因字号小、放在角落、括号里、末尾或换一种说法而放行。

## 禁止范围

- 讲制作方式或生成来源：AI/人工辅助、模型生成、仅作展示等。
- 讲作者身份或经历归属：不是作者亲历、非本人经历、不代表本人观点等。
- 讲材料性质：教学/练习示例、虚构/演绎/模拟、请换成自己的经历、不要原样套用等。
- 讲用途、免责或解释责任：仅供参考、不构成建议、效果因人而异、免责声明、创作说明、补充说明等。
- 换成“注”“温馨提示”“PS”“说明一下”等引出的同类文案，或移到标签、气泡、截图、签名、水印及正文分隔线之后。

按句子的用途判断，不只匹配关键词。正文讲清知识本身、步骤原因、真实条件和操作方法仍应保留；不能把正常的面试回答、条件句或工具说明一并删掉。不能借这个要求删除会改变内容含义的数字、否定、适用条件或已知限制，应将它们写进相关内容句；无法准确表达时删去对应主张，不靠免责尾注兜底。

## 起草与资料分开

1. 阅读 Humanizer 后，在起草每个对外字段时同时应用本规则；先清掉所有声明、解释类附注，再固定正文与每张图的准确文字清单。
2. 来源、生成方式、教学/虚构性质、未核实事项、审查理由、授权与进度如实保留在过程资料，不能复制进发布文案或作为图中文字。上游许可、品牌来源及历史发布证据照常保存，不改写成“从未出现过”。
3. 不用补造作者亲历、身份、数据、用户评价或产品效果替代被删附注。没有亲历材料时，用“如果被问到……可以这样组织回答”之类的场景/条件表达承载内容，不添加解释例子性质的句子，也不写成“我当年就是这样拿到 offer”。
4. 主参考或历史样稿带有上述附注时，只取有用结构，不把它们继承到新稿。Humanizer 通用参考中“保留免责声明/资料缺口/示例标识”不能成为向小红书成品加附注的理由；缺口和性质留在过程记录。

## 出图前与出图后

生成提示词须包含以下约束，并把已审文字逐项列全；不要把内部资料段或禁止文案样例作为可见内容传入：

> 图中只允许准确文字清单中的内容，不得自行增加任何声明、解释或免责文案；页脚、小字、括号、气泡、贴纸、截图和水印位置同样禁止。不要说明制作来源、作者身份、经历归属、示例性质或使用责任。没有列入清单的文字一律不生成。

生成后打开每张实际图片，逐项对照文字清单，并查看清单之外的小字、气泡、页脚和角落；文字识别只作辅助。发现附注即判不合格，保存旧稿、更新提示词，只修该页明确问题，再实看核对。不能仅改提示词就记录通过，也不能缩小、挪到角落、模糊或盖上品牌蒙混。

成稿审查同时检查最终标题、正文、图片和待提交参数，任一位置残留即退回；内部通过记录须写出检查了哪些字段/图号及是否发现新增文字。审查前已被批准的内容若改动，仍按现行任务授权规则处理，不在执行器发送时偷偷改稿。

## 内部判断样例（禁止复制进成品）

| 待检查文字 | 结论 | 处理 |
| --- | --- | --- |
| 配图为 AI 辅助生成；文中经历为教学示例，不是作者亲历。 | 不通过 | 整句移除，生成来源和材料性质只留过程资料 |
| 练习示例，请换成自己的经历 | 不通过，图片中同样如此 | 删除该标签，用任务场景和条件句直接进入回答 |
| PS：内容仅供参考 | 不通过 | 删除，不能换成“温馨提示”保留 |
| 如果被问到社群运营，可以先讲自己参与过哪部分，再说接手后的第一步。 | 可保留 | 它在讲主题本身，没有额外声明 |
| 我还没独立负责过社群，但做过活动报名和现场答疑。 | 视语境与资料核对 | 可作条件场景中的回答；无依据时不得写成作者亲历 |

本规则约束 agent 编写的对外文案；平台自身显示的字段与界面不在图片上仿造，也不由 agent 虚报或规避。
