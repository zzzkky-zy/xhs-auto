# 帖子制作：直接执行原 skill

先执行[最新内容要求](content-requirements.md)，再结合以下原方法制作；原文冲突处按最新用户要求覆盖。

先读[原文与后来新增要求的关系](../../../docs/CONTENT-SOURCES.md)。本页只连接原 skill、后来新增的能力与现有发布程序，不另写一套内容标准。

## 必须读取的原文

1. [图文方法 全文](original-skills/xiaohongshu-baokuan/SKILL.md)，以及它要求读取的 references、质量补丁和红线清单。制作与审查前完整读[原现行 workflow-checks](original-skills/xiaohongshu-baokuan/references/workflow-checks.md)，阶段与自审按当前方法。
2. 配图所需的 [sweety-xhs-images 原 skill](visuals/xhs-series.md) 及完整 references；[系列图原方法入口](visuals/workflows/README.md)直接连接原分析、提纲和提示词文件。

这些文件是当前制作与质量审查的依据，原步骤、样例、主参考、视觉多样性和审查要求完整执行，不能用迁移版概述或自写替代样例代替。热门池只执行用户最新明确条件：至少50篇，点赞/收藏/评论任意一项严格超过200；原文各处的30篇、超过500不再执行。

## 结合后来新增的要求

- 起草前读 [Humanizer-zh 原 skill](../../humanizer-zh/SKILL.md)，实际草稿完成后再编辑该稿；接入方式见 [Humanizer](../../../docs/HUMANIZER-ZH.md)。它与两份原帖子 skill 一起使用，不替代原来的创作、样例和红线审查。
- 制图按[视觉入口](visual-production.md)接入后来增加的信息图、封面、漫画、gbro-cover-design 和 Naturalizer；原系列图方法直接读取完整原文件。每批每帖按各原 skill 的方法选择不同的预设风格，见[批次风格要求](visuals/batch-styles.md)。真人只用于封面，且必须用首次配置中用户上传的真实人脸；内页仍无真人。用户删除的画风、指定品牌原素材等后加要求见[内容来源与例外](../../../docs/CONTENT-SOURCES.md)。
- 标题、正文、所有配图与互动文案执行[禁用附注文案](audience-copy.md)，起草、提示词和最终实际图片都检查。

## 控制重复工作与交接等待

- 同批共用一个去重研究池，先用搜索已返回的指标、标题和可见信息排除重复、不达标及明显无关的广告候选，再完整读候选正文和全部配图；读过的同一目标可同时支持选题和评论。达到50篇真实合格来源且覆盖本批题目后固定池子，转入制作，不为“再多看一点”继续搜。
- 完整规则同批读一次并留下已读路径；后续按具体字段和相关原文复核。同批阶段稿、来源快照和准确图片文字直接复用，实际内容变化才重做受影响的阶段。换会话按已登记进度接续，缺少具体原文上下文时再读取。
- 搜索、读帖和外发保持账号串行；已有等待期间处理离线阅读记录、文案构思或图片方案。进入制图后，不依赖同一张图的其他页可独立生成；每张图仍分别实看，不因并行省略验图。
- 只对确需最新内容的评论目标刷新，不在发布前重刷整池或重复登录探测。按程序返回的原期限及时接续；身份检查后留下的短等待不拖到身份缓存失效再开始。
- 在最终审查前固定本批数量、评论策略与替换关系、实际标签、图片顺序和预约参数，排期及平台时间档位按[运行规则](../../../docs/RUNTIME.md)处理；不为了等全批制作完而延后真实source、draft、edited阶段的登记。之后集中审查已完成条目，准备就绪且计划不再变化的评论可在制图期间按原节奏发送。参数变化时只重新制作、登记实际受影响的材料，再按程序要求重新绑定审查，不重做未变的研究与图片。
- 同一故障已在不同目标重复出现时，停止该类外发并转入诊断，不靠继续换帖试探。其他已有资料支持的离线制作继续，成功及未知记录保留。
- 开始执行即保存带时区的起始时间；在现有任务资料记主要阶段起止、完成物与阻塞原因，同时保存“全部提交获确认”和“后台核验及交付完成”两个时刻。总耗时从开始连续计算，包含等待、中途对话和接续；阶段若交错进行不得直接相加，不能把预约公开时间算成实际提交时间。进度写真实成品数及确认发送数，交付前同步更新验收文档、回执和后台实际预约时间，避免文档仍写“正在提交”。
- 出现耗时卡点先定位重复读取、交接等待或故障，再做针对性调整；速度不能靠降低资料门槛、补写审核或略过实际验图换取。对本次复盘后的下一轮同规模2篇/10条任务，以全部提交获确认不超过60分钟作为待验证的提效目标；不是超时停止线或通用完成保证，超时如实记录原因并继续已授权工作，不推广到其他规模。

## 沿用现有记录与发布程序

来源、真实草稿、Humanizer 编辑稿、实际验图与最终文案仍按[内容审查契约](../../../docs/CONTENT-REVIEW.md)保存并绑定。原红线审查的 pass/fail 照原文记录；Humanizer 的编辑记录另外保存，不拿它替换原红线。

账号、授权、发帖数量、排期、话题设置、工具参数、失败恢复和回执保存只走当前[运行规则](../../../docs/RUNTIME.md)、[MCP 契约](../../../docs/MCP-CONTRACT.md)及用户本轮实际约定。原目录中的旧发布脚本、端口、写开关和旧日程不运行。内容通过审查不等于获得新增发布授权。
