# 漫画完整制作流程（运营内页适配）

本流程保留上游的分析、角色、分镜、提示词、角色参考和逐页生成链。运行配置、队列、安装、供应商及发布不在这里处理；画幅和整帖页数服从运营流程，不默认生成长篇或 PDF。

## 1. 内容与已有材料

读取本轮资料、任务和已保存的草稿。按 analysis-framework.md 确定读者、核心问题、事实/教学示例、转折与结尾小目标；不覆盖已有 source、分镜、角色或通过页。先查现有记录和文件，只接尚未完成的阶段。

## 2. 选择表现方式

按 auto-selection.md 确定 art、tone、layout 或特殊 preset，读取对应完整定义。已有明确选择就沿用；未指定时根据内容说明理由，不重复进行首次偏好设置。特殊 preset 必须落实额外叙事规则，不能仅展开 art+tone。

## 3. 分镜与角色

按 storyboard-template.md 写每页每格的场景、景别、人物动作、道具、环境、准确对白/旁白、阅读顺序与页面作用。先写一个内容承诺，删掉不推动理解的重复场景。角色按 character-template.md 固定发型、衣服、配件、颜色、比例、表情和年龄变体。

ohmsha 依其预设保留师生角色、道具揭示、动作隐喻和完成小目标的结尾；不能变成两个人对着讲大道理。wuxia/shoujo 保留各自规定的动作/情绪语言，同时减少不承载内容的重复特效。预设默认角色与可定制方式见各自文件，不另造隐形别名。

Humanizer 从对白、旁白和标题起草时参与；事实、数字、限定与引用保持。教学/虚构例子与实际记录在内部资料分开，不能写成用户亲历；不要把这类材料性质说明加进正文、旁白、气泡或页脚，按[禁用规则](../../../../audience-copy.md)审查。

## 4. Naturalizer 与提示词

角色表、封面、每页漫画都先做 Naturalizer 方案：动作是否有支撑、视线指向谁、道具如何用、手和道具如何接触、尺度与遮挡是否合理、背景是否属于同一场景。夸张表情和气流是预设语言，不因“自然”删掉；技术说明和文字仍须准确。

按 page-prompt-template.md 合并选中 art/tone/layout/preset 的实际规则、角色定义、分镜、准确文字、具体避免项与统一视觉约定。提示词必须自足，不只写本地路径；更新页前先更新对应提示词，保留上一稿。生成前做统一审查；若用户要求先看分镜/提示词则等其意见，否则在已授权范围推进。

## 5. 先做角色参考表

用 characters/characters.md 中的角色表提示词生成一张参考表，常用 4:3，但按现有能力和角色数量安排。实看同一角色各角度的发型、服装、颜色、比例和配件是否一致；不合格先修角色表，不把错误带入所有页。角色表是过程素材，不能混入发布图片。

## 6. 每页顺序生成

- 支持图像参考：每页实际传入已通过的角色表，并在提示词写明要延续的特征。
- 不支持图像参考：在每页提示词嵌入本页角色完整定义，记录仅文字参考，生成后加强对照，不假称保证同脸。
- 有已通过无品牌页面时，可补作线条/材质/颜色锚点；不要借此机械复制同一格局。

每次只生成一页。按分镜阅读顺序实看对白、角色、道具、动作和过渡；与角色表及上一页比较。复杂页第一轮解决格子/文字区和阅读路径，下一轮只处理主体动作，再局部修错，保存每轮与唯一目标。当前页检查保存后才做下一页。

## 7. 收尾与交付

封面沿用无品牌；内页最后贴指定原品牌 PNG，不能交模型绘制。保留无品牌稿和最终稿；连看整套缩略图检验叙事节奏与视觉一致。记录每页分镜/提示词/图稿位置、角色表使用方式、通过项与未完成项。沿用主流程最多 3 轮审查返工。

只交付本轮要求的 PNG 与文案/说明。PDF 或长条导出仅在另有明确需求、宿主已有相应能力时处理，不调用未随包提供的脚本或安装 Bun。漫画完成不授权发帖。

## 页修改

编辑某页：改对应提示词 → 保留旧图 → 只修该页 → 复查角色/对白/动作。增删页：先调整分镜与引用、确认页数限制，再按新页序维护文件清单；不删除已完成素材或自动重做所有页。
