# 视觉制作入口

先根据内容选择制作方式，再选预设。这里仅指导内容和视觉；运行、授权、输出目录与任务状态仍以运营入口和运行契约为准。完整制作资源已随包保存，不必联网找定义，也不必另装上游生图工具。

先完整读取[原 xiaohongshu-baokuan](original-skills/xiaohongshu-baokuan/SKILL.md)及其配图质量补丁，再读[原 sweety-xhs-images](visuals/xhs-series.md)。系列图的来源分析、提纲与提示词直接读取[完整原方法](visuals/workflows/README.md)，不再采用迁移概述。下面的信息图、封面、漫画与 Naturalizer 是后来新增的制图能力，与原内容质量要求一起执行；原步骤、检查项和跨帖要求不因选择新模块而放宽。

每批开始选图时先读[每帖不同预设风格](visuals/batch-styles.md)：按本批实际数量，为每帖选择不同的现有预设风格；选择方法仍遵各个原 skill，并参考真实爆款及本题内容。不能只换颜色、标题或名字。整批方案检查和最终缩略图检查都核对这项要求。

用户允许真人出镜后才可使用此封面例外，cover_person_enabled=false时跳过真人模块。真人例外仅适用于封面：只能使用[首次配置的真实人脸参考图](continuous-operations.md)，保持同一个人的长相，不生成虚构人脸；内页继续执行原来的无真人规则。选择真人封面时完整读取下表 gbro-cover-design，实际传入已核对的参考图；无法传图时该真人封面待完成，不以文字描述代替人脸。其他封面方式继续保留；按私人配置的每批真人封面最低数量先安排真人封面，当前用户要求每批至少一篇，其余依据内容自主选择。

## 先选这一张承担的任务

| 读者需要什么 | 制作方式 | 读取入口 |
| --- | --- | --- |
| 滑动阅读主题，逐页拿到方法、示例或话术 | 小红书系列图 | [系列图规则](visuals/xhs-series.md)，再读所选画风与布局 |
| 在一张图中看清比较、分类、层级、数据、流程或系统关系 | 专业信息图 | [信息图规则](visuals/modules/infographic/guide.md)，再读布局和画风完整定义 |
| 第一眼理解主题、愿意点开，详细内容由正文或内页承担 | 独立封面 | [封面规则](visuals/modules/cover/guide.md)，再读六个维度与匹配规则 |
| 适合由用户配置的人物出镜吸引阅读的封面 | 真人封面 | [gbro-cover-design](visuals/modules/gbro-cover-design/guide.md)，完整原 SKILL、所选构图模板与示例，人脸用私有配置中的真实参考图 |
| 通过人物行动、对话、误解与变化理解问题 | 漫画 | [漫画规则](visuals/modules/comic/guide.md)，再读画风、基调、分镜和特殊预设 |

按页选择，不强迫整篇只用一种模块。可用独立封面接信息图内页，或系列图插入一页漫画。信息图的 `comic-strip` 适合短序列解释；需要跨页角色、动作连续和剧情时用漫画。只有信息条目而没有故事动作，不为装饰硬选漫画；正文很长也不等于应全塞进信息图。

同帖共用一个视觉约定：主题与标题承诺、语言、画布、主色/强调色与色值、字形层级、线条/材质、角色或主物件、页码与品牌位置。每页注明模块及变化理由。例如封面用 cover 的 warm + hand-drawn，内页用 infographic 的 morandi-journal，可延续奶油底、青绿、橙色强调与纸笔材质；不能仅因都叫“温暖”就认定一致。封面只作配色/材质参考时，不照搬它的稀疏构图到内页。

## 每张都从文字与视觉方案开始

所有模块同时执行[对外文案禁用规则](audience-copy.md)：出图前清理准确文字清单，提示词明确禁止新增声明、解释或免责附注；出图后实看正文之外的小字、页脚、气泡和角落。有残留即退回，只修对应页，不靠移动或缩小文字放行。

1. [Humanizer-zh](../../humanizer-zh/SKILL.md) 参与标题、配图文字和正文的起草与核对，保留事实、数据、条件与引用。固定本页准确文字清单后，模型只负责呈现，不能临场续写。
2. 所有图片类型，包括真人封面和漫画角色表，都先读 [Naturalizer](visuals/modules/naturalizer/guide.md) 及它的两个参考文件。它参与用途、读者、主体/场景、构图、信息层级、阅读顺序、光线/材质/尺度、姿态与物体功能的设计。平面、像素、夸张漫画等写明有意抽象的部分及不适用项，不强加摄影效果。
3. 读取所选模块与完整预设，不只抄名称。把采用的颜色、笔触、渲染、布局、标注或对白规则和具体避免项写入 [单图提示词模板](visuals/prompt-template.md)。提交的是已填实的自足提示词，不是文件路径或一串风格词。
4. 生成前按 [内容与视觉审查](visuals/review.md) 检查方案，生成后实看图片，用同一文字清单、阅读路径与约束对照。“提示词写了”不等于“图片做到了”。

## 保留风格，减少同屏负担

保留风格识别感：系列图的小场景/卡通主体、色块与少量贴纸；丝网印刷的剪影和网点；水墨笔势；像素格点；技术图的精确线条。减少的是同时出现的对象、装饰、关系层级与重复文字，不把所有模块都改成卡通或白底文字卡。study-notes 的笔压和 retro-pop-grid 的严格网格也按各自定义保留。

只为阅读目标添加元素。数据不足不能为填满布局编数字；字多先删重复、拆页或放正文，不缩成手机看不清的小字。高密度信息图和密集分镜仍可用，但要有足够真实内容和可读空间。

复杂图分轮：先固定结构、文字位置与阅读路径，下一轮只处理主体/关系，再下一轮只修一个发现的问题。简单图不为流程多生成。每轮保存上一稿，写明本轮唯一目标；不一次同时解决多角色、密集中文、多层关系和完整品牌。

## 逐张制作、检查、保存

沿用 1080×1440 PNG、每帖最多 5 页（含封面）。只有任务另行指定才改；上游的横版、宽屏、长漫画参数不自动覆盖小红书交付要求。漫画角色表是过程素材，不计作发帖页。

一次只生成一张：方案 → 提示词 → 无品牌图 → 实看 → 必要局部修正 → 品牌叠加 → 保存可用稿，再做下一张。漫画一页数格属于分镜，不是把整篇所有页拼成一张。

最终发帖 PNG 单独放在本帖的图片交付目录；角色表、无品牌稿、旧稿和提示词放在本帖过程资料区，不混入待发布图片。现有 `check_assets.py` 会递归检查目录内所有 PNG 为 1080×1440，因此只把最终图片目录交给它，不把含 4:3 角色表的整个资料目录交过去；不为参考表改动发布尺寸规则。

沿用任务现有记录，在内容交付说明中补充每页文件、模块/维度、提示词位置、当前图稿、通过项、问题和下一轮目标即可，不另建队列、数据库或调度器。中断后先读记录和现存文件，只接未完成页；已生成未检查不能算完成，已通过页不重新生成。

## 宿主出图与品牌收尾

优先用宿主已有图像生成/编辑能力，按实际接口调用。能传图时传无品牌锚点或角色表；不能传图时嵌入具体描述并加强一致性检查，不假称传了图。不引入新供应商或额外付费服务，不照搬上游 API Key、并发、重试或安装流程。能力不可用就保存方案与提示词，标记“配图待完成”，不拿占位图当成稿。

真人封面不使用上段的“不能传图时嵌入描述”替代办法：必须实际传入用户上传的真实人脸参考图，按 gbro-cover-design 原文保持人脸一致性，并实看成图与原图对照。参考图的长期原件放包外私有资料目录，不进入源码、安装包或会被批次清理的目录；本批使用准确副本并沿现有来源记录绑定。

品牌最后叠加本包原 PNG，来源与校验和见 [品牌清单](../assets/brand/manifest.json)。封面沿用不贴品牌；内页浅底墨色、深底白色，等比宽 180–240px、右下边距至少 48px，不遮挡标签或对白。模型不生成、改字、描摹、变色或旋转标志；不把带品牌稿作为重新生图的品牌参考。保留无品牌稿与最终稿。

逐张实看并连看整套缩略图，核对文字、结构、风格、角色与品牌。格式检查不能代替实际视觉验收。预设范围和来源见 [资源目录](visuals/resource-catalog.json)、[上游来源](visuals/UPSTREAM.md)。
