# 小红书自动运营

先按[规则优先顺序](../../docs/CONTENT-SOURCES.md)解决冲突；用户已经明确的要求直接执行，不重复确认。制作与自审先读[最新内容要求](references/content-requirements.md)：完整读取私人产品原文，恢复帖子原 CTA，B/C 评论写足产品用途和私信免费体验，按私人配置满足每批真人封面最低数量。最新用户要求覆盖旧文档相冲突的限制，不从历史失败自审继承额外禁令。

所有对外内容先执行[文案禁用规则](references/audience-copy.md)：标题、正文、全部图片及评论/回复均严禁声明、解释、免责类附注文案；起草、出图提示词和成稿实看同时检查，不因旧样稿或其他参考要求保留而例外。来源与材料性质只留内部过程记录，不补造亲历。

本包以小红书运营 skill 为入口，包含两条业务流程。内容制作先读[原文与后来新增要求](../../docs/CONTENT-SOURCES.md)：帖子完整读取图文方法及参考，评论直接完整读取 soft-cta；只读取当前方法及本次所需参考。开始任何内容制作前，先读取随包 [Humanizer-zh](../humanizer-zh/SKILL.md)，在起草中应用，并逐项核对成稿：选题表达、标题、封面与配图文字、正文、评论、回复、互动话术以及交付说明都在范围内，不能仅在审稿时调用。原帖原话、数据和结构化参数不改写；具体接入见 [内容制作与 Humanizer](../../docs/HUMANIZER-ZH.md)。所有图片在出图前使用随包 [Naturalizer](references/visuals/modules/naturalizer/guide.md) 形成视觉方案与可生成提示词，生成后对照实际图核查；Humanizer 管文字，Naturalizer 管视觉，两者各自贯穿制作。运行位置、配置、工具字段、账号会话、限频、恢复以 [运行契约](../../docs/RUNTIME.md) 为唯一权威；内容方法与工程入口使用本包有效文件。

## 首次使用

首次配置完整执行[逐步引导](references/first-time-setup.md)：默认当前设备与自动私有目录，打开浏览器让用户登录；逐项问清业务资料，说明现有禁区及默认评论/动作，再明确运营任务。先制作1篇图文和5条评论本地样稿，按用户反馈建立表达样例；真人封面先问是否允许，允许才收模特照片。质量标准沿用当前规则，不询问长期运行/通知配置。已有账号沿用原资料，不因升级重走引导。

## 云端工具浏览器

配置 `browser_mode=cloud_host` 时，先读[云端适配](../../docs/CLOUD-HOST-BROWSER.md)，使用专用四个云端工具或命令入口。请求只是待执行计划，必须通过宿主受支持浏览器工具实际导航和读取，再记录观察；不能将计划当成结果。此模式只支持公开读取，不执行下文的发送、登录、长期调度流程，不能回退到未知 CDP。原本机配置继续使用既有流程。

## 先检查

1. 默认当前使用设备，agent自动核对实际宿主能力，不向用户询问设备。在本 skill 上两级找到完整包目录，从该目录调用程序，不依赖当前工作目录。配置位置优先用调用者明确提供的路径；未提供时检查 `${XDG_CONFIG_HOME:-~/.config}/xhs-operations/xhs.local.json`，缺失时按 [Codex 本地入口](../../docs/CODEX-LOCAL.md) 准备独立私有配置。取得已批准的任务范围，使用已连接MCP的正常读取或诊断入口；只有服务不可达、配置变更或接手需核对时才查 `get_runtime_status`，必要时用同配置 `service ensure`。普通搜索、读帖和诊断不为此创建批次或任务库。health 只证明进程/CDP 可达，不证明登录、配图、发布或云端验收。
2. 遇未知提交先读任务记录并 `reconcile <任务编号>`，不能直接重新入队或换编号发。原未知未核清时自动队列保持暂停；只有用户明确新增授权的不同目标可独立直接调用，旧未知保留，新动作单独记账，不能拿新编号重发旧内容。遇到300013/ERR_RATE_LIMITED先保留任务，停止相关请求；不反复试搜、不把限流当掉线或已登录，不自动重登。具体静默期与恢复以运行契约为准。验证码、登录过期、账号不一致、权限或额度不足均保存进度并等待处理；不自动刷新登录、发送验证码或换设备。
3. 每日目标、实际批次数量、关键词、执行时段与日程按用户最新约定并保存来源。热门池只执行至少50篇、点赞/收藏/评论任意一项严格超过200；不再执行原文30篇/超过500，也不由agent自行调松。其他内容要求直接读取原 skill，只有用户明确后加要求可以覆盖。帖子使用平台预约发布，相邻对外发布时间随机间隔60–90分钟；评论/回复随机间隔1–3分钟，随机结果落盘后沿用，不重启重抽。随机节奏不证明免风控；搜索仍受独立访问预算约束。
4. `allow_write=false` 是交付默认值。首次完整实跑需实际发送授权，并由用户验收内容质量；用户确认持续运营授权后，后续同一账号、已约定业务范围内的新选题、新稿和新图片由agent内部审查，不逐帖向用户请示。首批未验收不能自行标记通过；但本次已有明确发布授权且无需审核时，沿该指令自审执行，approval_ref引用原指令，不把长期验收当作逐条审批。账号或业务范围改变时按新的实际授权处理。具体机制读[持续运营与清理](references/continuous-operations.md)。
5. 真人封面为可选项，按[首次引导](references/first-time-setup.md)记录 `cover_person_enabled`。用户拒绝则无需照片并正常完成其他配置；允许才请上传模特照片，实看并存包外私有目录及原配置，记录路径、哈希和用户来源。允许但缺图时标记待补，不能用AI人脸代替或宣称真人就绪。已有用户明确要求真人封面即视为允许，沿用其已提供参考图并按已确认的每批最低数量执行，不重复询问、不重建任务。

## 选择任务

- 在别人的帖子下评论或回复：完整读 [原 Soft CTA](references/original-skills/soft-cta/SKILL.md)，再读 [Humanizer 与当前程序接入](references/comments.md)。原文的先主评后回评顺序必须执行。
- 研究并制作求职/面试图文，准备或获准发布：完整读 [图文方法](references/original-skills/xiaohongshu-baokuan/SKILL.md) 及所需参考，再读 [Humanizer 与当前程序接入](references/content.md)；制图先读 [视觉入口](references/visual-production.md)和[每批每帖不同预设](references/visuals/batch-styles.md)，按各原方法结合爆款和内容选择系列图、信息图、独立封面、gbro-cover-design 真人封面或漫画，再读取对应完整预设和制作规则。真人封面仅在用户允许后使用其提供的模特真实人脸，内页无真人。封面与内页可用不同模块，沿用同帖视觉约定；保留风格表现力、减少堆叠，逐张制作检查保存，复杂图分轮完成，不默认退成纯文字卡。
- 故障、重启、移交或升级：读 [运行契约](../../docs/RUNTIME.md)、[接手入口](../../HANDOFF.md)。
- 一次验收后长期运营、资源清理、自主修复或云端接手：读[持续运营与清理](references/continuous-operations.md)，使用manage_operation_run保存真实进度。
- Debian云端或低资源长驻：额外读[云端资源配置](../../docs/CLOUD-RESOURCES.md)，使用匹配预编译包、单个已有浏览器和远程制图能力；先核对实际宿主限制，不加载全部视觉参考或本地模型。

发布确认与未知处理另见 [发布恢复](../../docs/PUBLISH-RECOVERY.md)。主站身份、创作平台和云端浏览器分别检查；不要用“创作中心能打开”或“公开推荐能加载”代替评论所需身份。

## 每次执行

速度与质量一起验收。开始时复用CURRENT-RUN及已登记阶段；同批完整读过的规则和来源沿用，不逐帖重读整套规则、不为接续重搜整池。热门池满足50篇门槛且覆盖本批题目后停止扩搜，只有具体信息缺口才定点补读，马上进入制作；各项完整阅读、真实阶段注册、Humanizer与实际验图照常完成。网页等待期间整理已读资料、准备稿件和图片方案，不在程序保存的期限之外另加等待；接续到期动作时及时调用，避免离线准备过久导致身份缓存反复过期。每个主要阶段记录起止时间、实际产物与阻塞原因；汇报区分网页等待、制作和故障。具体执行见[帖子制作](references/content.md)。

研究和创作由 agent 完成，实际网页动作由 MCP 执行，任务执行器只管持久记录与单步调用，宿主负责唤醒和通知。每份计划与素材写到配置的 `output_dir`，引用来源、审查结论与批准记录同批保存。

开始制作前用manage_operation_run(operation="status", data={"include_profile":true})读取完整私有运营配置，再打开product_materials所列原文；普通status只有版本号，不能当作读过业务资料。确认本批评论策略；按实际发生的source→draft→edited→final阶段分别留存来源、完整初稿、Humanizer编辑稿及业务复核。用`content_id`将审查绑定这些文件、配置版本、计划和最终发送参数，不能用`humanizer_checked=true`等勾选替代过程与审读。具体字段和返工失效规则见[内容审查契约](../../docs/CONTENT-REVIEW.md)。

在最终审查前确认当前账号的话题模板和标签；若找不到私有配置指定的话题模板，则跳过该模板，改用与本帖内容最相关的标签（tags），记录原因并继续发布，不反复打开空模板列表或切换账号寻找；发送参数有变化时按新参数更新审查。

批次执行先固定数量、替换关系、标签与预约排期，再对真实完成的阶段稿集中做最终审查；等待与失败处理按[运行规则](../../docs/RUNTIME.md)，避免改计划造成重复审查。交付同时报告全部提交完成和后台核验完成的时刻、从开始累计的总耗时及未完成项；提效目标与实际结果分别记录，详见[制作与计时](references/content.md)。

普通动作直接调用已有MCP：搜索、读帖与诊断直接读取；评论、回复、图文和视频用原发送工具提交已审固定稿，一次调用内部完成核对、执行和持久归账。只新增可选 `run_id`、`approval_ref`，已有 `operation_id` 沿用；不填 `run_id` 时按目标、文字和素材唯一匹配已审条目，匹配不唯一则返回具体缺项，不让agent猜。管理字段不参与内容指纹。旧 `submit_task`、`reconcile_task` 保留兼容和恢复用途，不要求普通发送先建任务再手动归账。

只有跨时间、退出后接续或批量后台执行才用 `submit_task(tool, payload, approval_ref)` 保存固定参数，记录任务号和下一时刻；`get_task_status` 沿原编号查询，`control_task_queue` 管领取。旧队列不因升级或直接调用自动启用；宿主负责退出后的唤醒，不在agent后台长睡。原CLI `tick` 仍一次最多处理一条。所有路径共用账号串行与已保存随机1–3分钟写间隔，未到期直接返回下一时刻；这不保证免验证码。

输出区分：已研究/已制成草稿/待批准/已提交并得到确认/结果未知/等待人工。保存任务编号、明确错误码、素材位置及下一步；成功记录来自真实工具结果，未知状态不能计入成功数。本地告警由 `get_runtime_status` 或 CLI 的 `status` 提供，向用户送达仍需要宿主支持和已授权的渠道。临时故障会有限恢复；未知提交先自动查已有账本，不能确认就保留待核对。

拟真人操作：先读原帖与准确目标评论，再写具体且有用的原创内容；复用宿主正常浏览器会话，低频串行执行。评论阶段失败按 [评论恢复说明](../../docs/COMMENT-TIMEOUT.md) 处理；不靠反复搜索、重复点击或重登推进任务。验证/限制次数、成功率和人工介入逐次记录，不能将随机延迟当成避免风控的证明。

效率与任务参数见 [运行契约](../../docs/RUNTIME.md)。研究先复用本批已经读到的热门池；相同搜索默认复用15分钟，新搜索默认随机间隔60–90秒且滚动一小时最多20次。查询和图文/视频提交由程序在执行前统一排队，定时帖也执行配置的发布提交间隔。收到本地 `ERR_RATE_LIMIT` 保存同一任务和下一次时刻，后台到点自动继续，不连续重调、不另加固定等待；真正 `ERR_RATE_LIMITED` 的暂停不会自动恢复。以上是本包运营默认值，不是平台保证。搜索/详情可用 `compact`、`result_limit` 减少无关返回；确需重新核实才用 `fresh=true`，仍受预算约束。读取结果中的 `cached` 和原 `read_at` 必须如实保留，精简返回或复用热门池不代表刚完成全量采集。

换agent继续同一任务时，先查get_runtime_status中的pending_tasks、next_at和output_dir，再用原任务编号读取结果与阶段。沿用本批来源、已审最终稿、素材及授权，不因更换agent重新研究、重做图片或另编号发送。实际网页动作共用随机间隔，读取另受滚动小时120次预算，搜索还受自己的随机间隔和小时20次约束；默认范围以运行契约为准。研究可复用15分钟的详情与搜索快照；缓存命中只读本地旧结果，不触发登录探测，也不证明此刻仍登录。准备具体评论/回复时只对需要最新内容的目标fresh核实，不把整池重刷。真实fresh详情会重新加载，保留原样的cached和read_at，不把历史样本冒充实时结果。

若output_dir下存在CURRENT-RUN.json，先用它定位本轮材料、完成阶段和任务编号。该文件只是进度资料，不赋予新增发送授权；具体批准仍沿用本轮实际用户记录。

长期执行只保留当前批需要的素材与一份滚动状态摘要，全部批次产物写入带所有权标记的operation-runs目录。入队后保存原任务编号和下一时刻，由宿主唤醒，不常驻长睡或每几秒查询；图片逐张生成检查。资源不足先停止新增工作，待资源恢复沿原任务继续；不会为了清理删除未知证据、登录profile或防重发记录。更新后只留当前可用程序、一份必要回退与私有状态备份，核对引用后清除自己的旧候选、安装包和构建缓存，不清其他任务资料。
